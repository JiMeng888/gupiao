# 热门板块数据源改造（2026-10-21）

## 1. 问题

行情页「热门板块」在截图中的表现是：

> 暂无法获取板块排名 —— `getSectors 暂不可用：上游数据源故障，且该数据未使用内置演示数据替代`

## 2. 根因（两条，均已实测确认）

### 2.1 板块只有一条真实源

降级链是 `eastmoney → tencent → tushare → mock`，但 `getSectors` 只有东财实现。
东财一旦不可用，路由落到 `mock`，而 `mock` 对榜单类操作**策略性拒绝**（`acceptableAsFallback`），
于是抛 503——这正是截图里的文案（且 `actionLabel` 漏了 `getSectors`，用户看到的是裸露的方法名）。

改造前东财正处在 IP 级风控中，实测：

```
ResourceAccessException: I/O error on GET "https://push2.eastmoney.com/api/qt/clist/get"
  Caused by: IOException: HTTP/1.1 header parser received no bytes
```

风控期间四个镜像域（`push2` / `1.push2` / `82.push2` / `push2delay`）同时断，
而腾讯、新浪在同一时刻正常——说明这**不是本机网络问题，而是单源风险**。

板块榜缓存 TTL 是 60 秒，所以「一次抖动」会被放大成「整块面板一分钟不可用」。

### 2.2 东财的板块口径不适合做榜单

东财行业板块接口（`fs=m:90+t:2+f:!50`）返回 **496** 个板块，一级、二级、三级混在一起，
且响应里**没有任何字段标明层级**。实测（2026-10-21）涨幅榜前十：

| 排名 | 板块 | 涨跌幅 | 成分股数（f104+f105+f106） |
|---|---|---|---|
| 1 | 广告媒体 | +6.85% | **3** |
| 2 | 其他数字媒体 | +6.61% | **2** |
| 3 | 生猪养殖 | +3.79% | 10 |
| 4 | 电视广播Ⅲ | +3.26% | 13 |
| 5 | 电视广播Ⅱ | +3.26% | 13 |
| 8 | 林业Ⅲ | +2.41% | 4 |
| 9 | 林业Ⅱ | +2.41% | 4 |

两个后果：榜首长期是「两三只票」的微板块（两只涨停就让板块 +6.6%），
且同一板块以 Ⅱ/Ⅲ 两个层级重复出现。这对「资金在往哪个方向去」没有解释力。

## 3. 改动

### 3.1 腾讯实现板块榜（一级行业）

`TencentMarketDataProvider#getSectors` → `proxy.finance.qq.com/cgi/cgi-bin/rank/pt/getRank?board_type=hy`

- 返回 31 个一级行业（农林牧渔 / 电子 / 通信 …），成分股规模相当，天然可比；
- 自带**涨跌家数**（`zgb="73/103"`）与**领涨股**（`lzg` 含名称/代码/涨跌幅）；
- 该接口是 **UTF-8 JSON**，与本类原有的 GBK 文本接口不是同一套解码路径，
  因此新增 `fetchJsonUtf8`／`fetchBytes`（按 GBK 解会把「食品饮料」安静地变成乱码）；
- `sort_type=price` 与涨跌幅**无关**（实测乱序），其它取值直接报错（`code=1619377101`），
  因此只能全量拉回（31 条）后**本地排序**。

### 3.2 按操作的数据源优先级

新增 `app.market-data.sector-chain`（默认 `tencent,eastmoney`），由
`ResilientMarketDataProvider` 的「按操作覆盖降级链」实现，**只影响 `getSectors`**，
报价 / K 线 / 搜索仍按主链 `eastmoney → tencent → tushare → mock`。

约束（构造时校验，不满足直接抛 `IllegalArgumentException`）：覆盖链末位必须是兜底源，
否则 `degraded()` 会漏判「板块正在用演示数据」。

想把板块交回东财：`MARKET_DATA_SECTOR_CHAIN=eastmoney,tencent`。

### 3.3 其余加固

| 位置 | 改动 | 原因 |
|---|---|---|
| `ResilientMarketDataProvider#actionLabel` | 补 `getSectors → 板块榜单` | 503 文案原本把内部方法名贴给用户 |
| `EastMoneyMarketDataProvider#getSectors` | 有界重试（2 次 / 120ms 退避） | 实测该接口会单次返回空、紧接着同一请求成功 |
| `Sector` | 新增 `leaderCode` | 领涨股可点进个股页；东财读 `f140`，腾讯读 `lzg.code` |
| `CacheNames.SECTORS` | key 加源前缀 `eastmoney:10` / `tencent:10` | 两源共用缓存名但口径不同，裸 `#limit` 会让东财命中腾讯的列表 |
| `MarketSourceStatus` | 补 `tencent → 腾讯（真实行情）` | 主源可配成腾讯，缺失时顶栏显示裸英文标识 |

### 3.4 前端（`SectorBoard.vue`）

- **数据来源 tag**：读 `marketSource.servingByAction.getSectors`，演示数据标红；
- **涨跌家数占比条**：数字下方 3px 细条，「普涨 / 分化 / 普跌」一眼可读，缺失时不画条；
- **领涨股可点击**：跳 `/stock/:code`；
- **错误态加重试按钮**：上游抖动是最常见原因，重试是用户此时唯一能做的事。

## 5. 残留问题（本次未动）

1. `getQuote` / `getBars` 的缓存 key 仍不带源前缀。两源都是真实行情、语义相同，
   碰撞只会让 `servingByAction` 的来源标注偏一个 TTL，不影响数据含义——
   与板块榜（口径不同）性质不一样，故未「顺手统一」。
2. 板块榜目前只有「涨幅榜」一种排序。腾讯接口支持 `board_type=gn`（概念板块 805 个），
   若要加「概念 / 行业」切换，需要先定概念板块的噪声过滤规则（含「昨日连板」这类临时板块）。
3. README 中写死的测试项数已同步为 460 项 / 30 个类，但仍属易过期信息，以 CI 输出为准。
