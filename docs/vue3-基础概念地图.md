# Vue 3 基础概念地图（面试速记）

> 面向全栈实习生面试。每个概念 = 一句话 + 一个比喻 + 一个「股票分析师」项目里的真实例子。
> 这 9 个概念覆盖了前端基础题约 80% 的考点。

---

## ① 组件（Component）

- **一句话**：一个可复用的、有自己模板和逻辑的 UI 片段。
- **比喻**：乐高积木，用很多块拼出整个页面。
- **项目例子**：`frontend/src/components/` 里的 `BaseChart`（K线图）、`ChangeText`（涨跌文字）、`SourceBadge`（数据源徽标）。

---

## ② props —— 父 → 子

- **一句话**：父组件通过 `props` 把数据传给子组件，子组件只能读、不能改。
- **比喻**：老板把任务单递给员工，员工照着做，但不能篡改任务单。
- **项目例子**：
  ```vue
  <!-- 父：个股详情页 -->
  <BaseChart :stock-code="'600519'" :bars="klineData" />
  ```
  `stock-code`、`bars` 就是 props。

---

## ③ emit —— 子 → 父

- **一句话**：子组件不能直接改父组件的数据，只能通过 `emit` 发事件，让父组件自己处理。
- **比喻**：员工喊一声「老板，我做完了」，下一步由老板决定。
- **项目例子**：自选股列表条目点「删除」时，子组件 `emit('delete', itemId)`，由父组件（列表页）调接口、更新数据。

---

## ④ ref —— 响应式值

- **一句话**：`ref` 把值包起来，值一变，页面上用到它的地方自动更新。
- **比喻**：普通变量是「改数字没人知道」；`ref` 是「改数字的同时广播通知所有人」。
- **项目例子**：`stores/auth.ts` 里的 `const user = ref(null)`。登录后 `user.value = {...}`，顶栏立刻知道「登录了」。

---

## ⑤ computed —— 派生值（带缓存）

- **一句话**：`computed` 不存新数据，而是根据其他响应式数据「算」出来；依赖不变就不重算（缓存）。
- **比喻**：总价 = 单价 × 数量，不用单独存，随时能算，且单价数量没变就不重算。
- **项目例子**：
  ```ts
  const isLoggedIn = computed(() => user.value !== null)
  const displayName = computed(() => user.value?.nickname || user.value?.phone || '未登录')
  ```

---

## ⑥ v-if / v-for —— 条件 / 循环

- **一句话**：`v-if` 是「条件成立才显示」，`v-for` 是「遍历数组，每个元素渲染一遍」。
- **比喻**：`v-if` 是「有货才摆出来」，`v-for` 是「每件货都摆上架」。
- **项目例子**：首页 5 张指数卡片用 `v-for="item in indices"`；「登录/未登录」按钮用 `v-if="isLoggedIn"`。

---

## ⑦ 生命周期（Lifecycle Hooks）

- **一句话**：组件「创建 → 挂载 → 更新 → 销毁」的过程中有几个固定节点，可以在节点上挂代码。
- **比喻**：人的「出生 → 上学 → 工作 → 退休」，可以在节点办手续。
- **两个最常用**：
  - `onMounted`：组件**第一次出现在页面后**执行一次，适合「进页面就拉数据」。
  - `onUnmounted`：组件**销毁时**执行，适合「清理定时器、断开连接」。
- **项目例子**：个股详情页在 `onMounted` 里拉 K 线；`quoteSocket` 的 WebSocket 在 `onUnmounted` 里关闭。

---

## ⑧ 路由（Router）

- **一句话**：根据地址栏 URL，决定显示哪个页面组件。
- **比喻**：商场导览牌，走到哪层看哪层的店。
- **项目例子**：`/stock/600519` → 个股详情，`/news` → 资讯，`/watchlist` → 自选股。
- **路由守卫**：没登录访问 `/watchlist` 会被弹回登录页。

---

## ⑨ 状态管理（Pinia）

- **一句话**：多个组件要共享同一份数据时，抽到一个「全局仓库」统一管理。
- **比喻**：公司公共仓库，谁要用都来取，改也只改这一份，避免各自存一份不一致。
- **项目例子**：`stores/auth.ts`（登录态）、`stores/quoteSocket.ts`（WebSocket 连接）、`stores/marketSource.ts`（数据源）。

---

## ⚠️ 最容易踩的坑（重点背）

**computed 读 localStorage 不更新**：
> `computed` 只在「它追踪到的响应式依赖」变化时重算。`localStorage` 不是响应式数据，追踪不到，所以读了它等于「没有依赖」，首次算完就永久缓存，永远不更新。

- 正确写法：`isLoggedIn = computed(() => user.value !== null)`（读响应式 `ref`）
- 错误写法：`hasToken = computed(() => Boolean(getAccessToken()))`（读非响应式 localStorage）

## 进阶概念（第 2 部分）

### ⑩ watch vs computed —— 什么时候用哪个

- **一句话**：`computed` 是「算出一个值给我用」；`watch` 是「某个值变了，我要执行一段副作用（发请求、存缓存）」。
- **判断口诀**：想要一个「值」→ `computed`；想在「变化时做点事」→ `watch`。
- **项目例子**：「切到另一只股票，code 变了重新拉 K 线」用 `watch`；「根据价格算涨跌颜色」用 `computed`。

### ⑪ ref vs reactive

- **一句话**：`ref` 适合包装「单个基本值」（数字/字符串/布尔）；`reactive` 适合包装「一个对象」。
- **区别**：`ref` 用时要 `.value`；`reactive` 不用 `.value`。
- **项目例子**：`const user = ref(null)` 是单个值用 ref；复杂的「持仓组合」对象可用 reactive。
- **加分点**：Vue 3 官方推荐「能用 ref 就用 ref」，解构不丢响应式。

### ⑫ v-model —— 表单双向绑定

- **一句话**：让「输入框的值」和「变量」自动保持同步。
- **项目例子**：登录页 `<input v-model="phone">`，用户打字 `phone` 变量实时更新。

### ⑬ provide / inject —— 跨层级传数据

- **一句话**：祖组件 `provide` 提供数据，深层孙组件 `inject` 直接取，不用中间层层转手。
- **项目例子**：全局主题色、数据源状态等。你项目里全局数据多用 Pinia 管，这个了解即可。

### ⑭ 路由守卫（Route Guard）

- **一句话**：跳转发生前插一道检查，决定「放行还是拦下」。
- **比喻**：小区保安，有权限才让进。
- **项目例子**：访问 `/watchlist`、`/holdings` 前检查「登录没」，没登录就重定向到登录页。README 第 4 条 bug 就发生在这里——登录态判断错了，守卫误判「没登录」。

### ⑮ nextTick —— 等 DOM 更新完

- **一句话**：Vue 改数据后 DOM 不是立即更新，`nextTick` 让你等 DOM 真正更新后再执行代码。
- **项目例子**：列表渲染完后自动滚动到某元素、测量元素高度等，要放 `nextTick` 里。

### ⑯ slot（插槽）

- **一句话**：子组件留一个占位，父组件用的时候把自定义内容塞进去。
- **比喻**：相框（子组件）里塞照片（父组件的内容）。
- **项目例子**：`ChangeText` 组件接收要显示的文字，只负责决定「涨红跌绿」。

## 进阶概念总表

| # | 概念 | 一句话 | 何时用 |
|---|---|---|---|
| ⑩ | watch | 值变了执行副作用 | 监听变化发请求 |
| ⑪ | reactive | 响应式对象 | 包装一个对象 |
| ⑫ | v-model | 双向绑定 | 表单输入 |
| ⑬ | provide/inject | 跨层级传数据 | 深层组件共享 |
| ⑭ | 路由守卫 | 跳转前检查 | 登录拦截 |
| ⑮ | nextTick | 等 DOM 更新 | 更新后操作 DOM |
| ⑯ | slot | 插槽占位 | 父填子内容 |

**高频必背**：⑩ watch、⑪ reactive、⑫ v-model、⑭ 路由守卫。
**了解即可**：⑬ provide/inject、⑮ nextTick、⑯ slot。
