五、发现的问题（均非本次改造引入，待决策）

问题 1 · all 聚合被两个频道垄断，后三个频道永远进不来

实测 all 的频道分布，在多个 limit 下结论一致：

limit 8
财经5 · A股3
limit 20
财经13 · A股7
limit 30
财经18 · A股12

港股 / 美股 / 全球市场 0 条。 原因：NewsService.aggregate 拉取全部频道后按 ctime 倒序取前 N 条， 而 finance 与 a-shares 更新更频繁，把名额占满—— 30 条的截断线是 10:14，而 hk/us 只覆盖到 07:45，全部被挤出。

建议：聚合改为「按频道配额轮询」而非「全局时间排序」，或提高预取量后按比例取样。

问题 2 · global 频道内容停更 3.4 年 + 涉政风险

频道最新一条内容性质
global · 153/25142023-05-10观察者网 / 环球网国际时政（北约、台海、中日）

比此前判断更严重——不只是内容与标签不符，而是整个栏目早已停更， 同时仍会向首页推送涉台海、涉北约标题，存在合规风险。建议下架该频道。

问题 3 · hk 与 us 是同一个栏目

两频道时间范围完全一致（11:17:46 ~ 07:45:57），首条标题完全相同。 即 153/2518 与 384/2672 指向同一份内容，只是新浪提供了两个入口。 首页若同时展示会出现重复条目（当前因问题 1 而未暴露）。

六、一次目测误判的纠正

窄屏（969px）截图看起来「轮播卡片内容几乎全不可见、只剩右侧一个碎片」， 一度判断为轮播的响应式缺陷。DOM 量测证明是假象：

轮播项内容溢出检查29/29 全部未溢出
轮播容器宽度903px / 426.5px，与视口匹配 ✓
el-carousel__item 的 minWidth0px ✓
截图里看到的是 translateX 过渡中间态被渲染了出来
真正撑宽页面的元凶.layout__actions（导航栏操作区，DefaultLayout.vue:237）
根因：.layout__actions 是 display:flex， 内含固定 width:240px 搜索框 + 状态标签 + 登录按钮， 无任何收缩策略（缺 flex-shrink / min-width:0 / flex-wrap）。 在 969px 视口下其右边界达 1081px，导致 document.scrollWidth = 1081 > clientWidth = 969，整页横向滚动。

这是导航栏的既有问题，与轮播改造无关。

教训（同类错误第二次）：窄屏或像素级布局问题一律先做 DOM 量测并设对照组，不要用截图目测下结论。
