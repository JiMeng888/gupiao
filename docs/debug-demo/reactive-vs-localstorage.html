🔬 响应式 vs localStorage —— 登录态 bug 现场复现

对比两个 computed：一个读 ref（响应式），一个读 localStorage（非响应式）。点按钮，看谁会自动更新。

实验一 · 读 ref（响应式）✅ 正常

判断逻辑：computed(() => user.value !== null)

登录状态： {{ isLoggedInRef ? '✅ 已登录' : '❌ 未登录' }}

实验二 · 读 localStorage（非响应式）❌ bug

判断逻辑（曾经的 bug 写法）：computed(() => Boolean(getToken()))

登录状态： {{ lsValue ? '✅ 已登录' : '❌ 未登录' }}

操作顺序建议：先点「写入 token」→ 看到状态没变（还是未登录）→ 再点「刷新页面」→ 状态才变成「已登录」。这就是「刷新就好了」。

一句话结论：computed 只在「它追踪到的响应式依赖」变化时重算。ref 是响应式的、能追踪；localStorage 不是、追踪不到，所以读了它等于「没有依赖」，首次算完就永久缓存，永远不更新。
