# 部署到免费服务器：可行性、方案与操作步骤

> 结论写在最前面：**能做到零成本长期在线，但只有一条路真正可行——Oracle Cloud 的永久免费 ARM 实例。**
> 其余"免费档"（Render / Koyeb / Railway）内存普遍 512 MB、CPU 0.1 核、还会休眠，跑不动这个项目。
> 如果你更在意"数据源稳、访问快"，**国内学生机约 99 元/年**才是最优解——它不是免费，但比任何免费方案都省事。
>
> 本文所有平台额度数据核实于 **2026-10-19**。免费政策变动频繁（Oracle 的免费 ARM 就在 2026-06-15 被砍半），
> 动手前请以官网当期页面为准。

---

## 一、为什么"免费服务器"这件事对这个项目特别难

这个项目的资源画像是**重型**的，不是静态博客那种级别：

| 组件 | 常驻内存 | 说明 |
|---|---|---|
| Spring Boot（JVM） | 350~600 MB | 堆 + Metaspace + 直接内存，`-Xmx` 压到 320 MB 是下限 |
| MySQL 8 | 300~400 MB | 仅 full 模式需要 |
| Redis 7 | ~30 MB | 仅 `SESSION_STORE=redis` 时需要 |
| Nginx | ~10 MB | 托管前端静态资源 + 反代 |

full 编排（4 容器）稳定运行要 **2 GB 以上**。主流免费档给的是 **512 MB / 0.1 vCPU**，
差了 4 倍内存、20 倍 CPU——这不是"调优一下就能塞进去"的差距。

> 这也是本次改动增加了 `lite` 模式的原因：去掉 MySQL 与 Redis，用 H2 文件库替代，
> 把下限压到 **1 GB 可跑、768 MB 勉强**。但它换来的是"能跑"，不是"好用"。

## 三、免费方案绕不过去的三个前提（比选平台更重要）

### 3.1 境外主机 → 行情源可能不可达（这是最大的坑）

项目的行情数据全部来自**国内财经网站的内部接口**：

```
push2.eastmoney.com    push2his.eastmoney.com   datacenter-web.eastmoney.com
searchapi.eastmoney.com
qt.gtimg.cn            web.ifzq.gtimg.cn        （腾讯）
```

东财本身就有 **IP 级风控**（服务端直接断连，2026-09-19 / 09-21 两次实测记录在
`docs/数据来源与授权状态说明-20260924.md`）。云厂商的境外机房 IP 段是这类风控的高危对象。

**所以：在买/注册任何境外主机之前，先在目标机器上跑这两条命令**——

```bash
# 1) 东财报价接口（最重要，榜单/搜索/财务都依赖它）
curl -s -o /dev/null -w 'eastmoney: %{http_code}\n' \
  'https://push2.eastmoney.com/api/qt/stock/get?secid=1.600519&fields=f43,f57,f58'

# 2) 腾讯报价接口
curl -s -o /dev/null -w 'tencent: %{http_code}\n' 'https://qt.gtimg.cn/q=sh600519'
```

两条都返回 `200` 且响应体里有内容，这台机器才值得部署。若东财不通、腾讯通，
把 `.env` 改成 `MARKET_DATA_CHAIN=tencent,eastmoney,tushare`——代价是**榜单与搜索会落到演示数据**
（腾讯不提供全市场涨跌榜和代码搜索）。

### 3.2 境内主机的备案与端口

- 境内（大陆）服务器用**域名 + 80/443** 对外提供网站服务，需要 ICP 备案，否则会被拦截。
- 仅用 `http://IP:8088` 做临时演示是常见过渡做法，但不应作为长期公开服务。
- 想免备案：用香港/境外地域，或只用非标准端口短期演示。

### 3.3 没有 TLS 就是明文传令牌

`frontend/nginx.conf` 只 `listen 80`，JWT 会以明文经过公网。做真实使用前，必须在前面加一层
Caddy / Nginx + 证书（Let's Encrypt 免费），或者用 Cloudflare 免费套餐代理并开启 Full 模式。

## 四、方案 A：Oracle Cloud 永久免费 ARM（零成本首选）

### 4.1 额度现状（2026-10 核实）

| 项目 | 额度 |
|---|---|
| ARM Ampere A1 | **2 OCPU + 12 GB RAM**（2026-06-15 从 4/24 砍半，8-18 起对超额实例强制回收） |
| AMD micro | 2 台 × (1/8 OCPU, 1 GB) |
| 块存储 | 200 GB |
| 出站流量 | 10 TB/月 |
| 期限 | 永久免费，无到期 |

**会被回收的条件**：任意 7 天窗口内，95 分位 CPU < 20% **且** 网络 < 20% **且** 内存 < 20%（仅 ARM）。
这个项目跑起来内存占用稳定在 40% 以上，基本不会触发；但保险起见可以挂一个 UptimeRobot 监控定时打一下。

### 4.2 注册与建机

1. 注册 Oracle Cloud，**家庭区域必须选日本/新加坡/韩国**（离国内近，且 ARM 容量相对好抢；区域选定后不可改）。
2. 信用卡只用于身份验证，Always Free 资源不会扣费。拒签很常见，被拒后换浏览器/网络，隔几小时再试。
3. 建实例：Shape 选 `VM.Standard.A1.Flex`，**OCPU=2、内存=12 GB**（不要超过，超额会被强制回收）。
   镜像选 Ubuntu 22.04 / 24.04。
4. **两层防火墙都要开**（漏一层就是"网站打不开"）：
   - 云控制台：Networking → VCN → Security Lists → 加 Ingress Rule，放行 TCP 8088
   - 系统内：`sudo ufw allow 8088/tcp && sudo ufw reload`

### 4.3 部署

```bash
# 装 Docker（官方脚本，ARM 架构自动选对应包）
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER && newgrp docker

# 拉代码（或本地打包后 scp 上传）
git clone <你的仓库地址> gupiao && cd gupiao/deploy
cp .env.example .env
vi .env          # 填 LLM_API_KEY；JWT_SECRET 留空由脚本生成

# full 模式（12 GB 内存足够，MySQL/Redis 都上）
./start.sh --build
```

访问 `http://<公网IP>:8088`。

> **构建耗时提醒**：2 核 ARM 上 `--build` 要 5~10 分钟（Maven 下载依赖 + 前端 npm）。这是正常的。
> 后续改代码再跑 `./start.sh --build` 即可，`./start.sh` 不加参数时不会重复构建。

## 五、方案 B：国内学生机（数据源最稳，约 99 元/年）

比免费方案更值得推荐的理由很直接：**行情源就在国内，延迟 20 ms 级，风控概率最低**；
而且 2 核 4 GB 跑 full 编排毫无压力。

1. 学生认证：阿里云「云工开物」/ 腾讯云「云+校园」/ 华为云「云创校园」，用学信网学籍报告 + 人脸核验。
   - 阿里云另有每年 300 元无门槛抵扣金，可抵掉一台入门服务器整年费用。
2. 地域选**离你近的**（华东/华北），系统选 Ubuntu 22.04。
3. 按 §4.3 的步骤装 Docker、部署。安全组放行 8088。
4. 学生机带宽通常只有 3~5 Mbps，**首次构建会比较慢**。可以在本地构建好镜像再传：

```bash
# 本地（x86 机器，需目标同为 amd64）
docker save deploy-backend deploy-frontend | gzip > images.tar.gz
scp images.tar.gz root@<IP>:/root/
# 服务器
gunzip -c images.tar.gz | docker load
./start.sh --no-build
```

## 六、方案 C：PaaS 免费档（Render / Koyeb）——不建议

原因是硬指标不够，不是配置问题：

- **512 MB 内存**：JVM 堆最多给到 ~320 MB，Spring Boot 4 + Security + MyBatis 启动后常驻接近上限，
  稍有并发就 OOM。
- **0.1 vCPU**：JVM 冷启动就要 60~120 秒，很可能还没通过平台健康检查就被判定失败。
- **15 分钟休眠**：免费实例无请求即挂起，下次访问冷启动 30~60 秒。面试演示时打开页面先白屏一分钟，体验很差。
- **无持久化磁盘**：H2 文件库写在容器本地盘，重启即丢——用户的持仓、自选股、分析存档全没。

本项目已做的适配（万一你要试）：`SERVER_PORT` 可被环境变量覆盖（PaaS 会注入随机端口）、
`lite` profile 去掉了 MySQL/Redis 依赖、`application-lite.yml` 的 H2 路径可用 `APP_DATA_DIR` 指定。
但**结论仍是：免费 PaaS 只适合验证镜像能不能起来，不适合给人用。**

## 七、本次为"能部署到小机器"做的改动

| 改动 | 文件 | 解决什么 |
|---|---|---|
| 新增 `lite` profile | `backend/src/main/resources/application-lite.yml` | H2 **文件**库替代 MySQL（重启不丢数据）、关 H2 控制台、限流用生产额度 |
| 新增轻量编排 | `deploy/docker-compose.lite.yml` | 2 容器、内存上限、H2 数据卷、后端只绑 127.0.0.1 |
| 端口可被覆盖 | `application.yml`（`server.port: ${SERVER_PORT:8080}`）+ `backend/Dockerfile` | PaaS 注入随机 PORT 时不再需要改镜像；健康检查同步用 `${SERVER_PORT}` |
| 限流开关可配 | `application.yml` + 两个 compose | 修掉"所有用户共用 nginx 一个限流桶 → 随机 429" |
| nginx XFF 改覆盖 | `frontend/nginx.conf` | 开 trust 之后客户端无法伪造 `X-Forwarded-For` 绕过限流 |
| 降级链真正传进容器 | `docker-compose.yml` | 上一轮加的 `MARKET_DATA_CHAIN` 之前**根本没注入容器**，写了也不生效 |
| 健康检查端口不再写死 | `deploy/start.sh` | 原来固定探 `localhost:8080`，与实际映射的 18080 不符，永远报"未通过" |
| 构建判断修正 | `deploy/start.sh` | 原来按 `grep stocklab` 判断镜像存在，实际镜像名是 `deploy-backend`，导致每次都重建 |
| H2 目录权限 | `backend/Dockerfile` | 先在镜像内建 `/app/data` 并 chown，否则命名卷是 root:root，非 root 进程写不进去 |

## 八、部署后必做的验证（5 条命令）

```bash
# 1) 后端健康（必须是 UP）
curl -s http://localhost:18080/actuator/health

# 2) 前端页面能返回 200
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8088

# 3) 数据源是否为真实行情（不是"演示数据"）
curl -s 'http://localhost:18080/api/quote/600519' | head -c 400

# 4) 一键冒烟（50 项断言，会注册临时账号）
BASE=http://localhost:18080 bash backend/scripts/smoke-test.sh

# 5) 公网端口是否真的通（从你自己电脑跑）
curl -s -o /dev/null -w '%{http_code}\n' http://<服务器IP>:8088
```

第 3 条最关键：返回体里的 `source` 字段如果是 `mock`，说明上游没通，先去解决 §3.1。

### 8.1 lite（H2 文件库）常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 容器反复重启，日志里 `Permission denied` / 打不开库文件 | `/app/data` 不可写。命名卷首次创建时继承镜像内目录属主，旧镜像里没有这个目录 | 确认镜像已重建（`Dockerfile` 里 `mkdir -p /app/data && chown -R app:app /app`），`docker compose -f docker-compose.lite.yml up -d --build` |
| `Database may be already in use` | 进程被 `kill -9` / 机器断电，留下 `stockanalyst.lock.db` | `docker compose -f docker-compose.lite.yml exec backend sh -c 'rm -f /app/data/*.lock.db'` 后重启。数据文件本身没坏 |
| 页面能打开，所有接口 404 | 前端镜像没重建，或 nginx 没配 `/api/` 反代 | 重建前端；`nginx.conf` 的 `/api/` 段不能删 |
| 登录 / AI 分析频繁 429，刷新几次就好 | 限流桶共用了 nginx 容器的一个 IP | 确认 `RATE_LIMIT_TRUST_FORWARDED=true`，且 `nginx.conf` 用 `$remote_addr` **覆盖** |
| 内存被打满、容器被 OOM killed | JVM 堆按宿主内存算（`MaxRAMPercentage=75`） | 显式设 `-Xmx`（lite 编排已给 448m；1 GB 机器改 320m） |

> 数据备份只有一条命令：
> `docker cp stocklab-backend:/app/data/stockanalyst.mv.db ./backup-$(date +%F).mv.db`
> 恢复时把它放回卷里同名路径即可（先停容器）。

## 九、安全清单（公网部署前逐条确认）

- [ ] `JWT_SECRET` 是随机生成的长串（`openssl rand -hex 32`），不是模板默认值
- [ ] `.env` 没有被提交进 git（`.gitignore:15` 已覆盖 `deploy/.env`）
- [ ] full 模式下 `docker-compose.yml` 里 mysql 的 `ports` 那段已删除（否则 3307 直接暴露到公网）
- [ ] `RATE_LIMIT_TRUST_FORWARDED=true`，且 nginx 用的是 `$remote_addr` 覆盖
- [ ] 已加 TLS 或 Cloudflare 代理，令牌不走明文
- [ ] 云厂商安全组只放行 8088（和 22），其余一律关闭
- [ ] 有备份：lite 模式 `docker cp stocklab-backend:/app/data/stockanalyst.mv.db`；full 模式 `mysqldump`

## 十、如果只是给面试看，怎么最省事

1. **首选 Oracle 免费 ARM**（0 元，full 模式，功能完整）。
2. **次选学生机**（99 元/年，数据源最稳，访问最快）。
3. 只想要一个能点开的静态展示页 → 把前端 `npm run build` 产物丢到 Cloudflare Pages（免费），
   但这样**没有后端**，登录/持仓/AI 分析全部不可用，只能看页面长相。

最后提醒一句：这个项目的行情数据来自未获授权的内部接口，公开部署等于把流量暴露给数据方，
存在被风控乃至收到律师函的风险（完整分析见 `docs/数据来源与授权状态说明-20260924.md`）。
**自己用、给面试官演示都可以；不要做成公开的"股票分析网站"。**
